# ФасадоФ: Production Deploy

## Repository Facts

- Frontend directory: repository root.
- Backend/API directory: same repository root, app routes under `app/api/`.
- Framework: Vinext + React 19 + Vite.
- Package manager: npm.
- Node version: `>=22.13.0`.
- Current database architecture: Cloudflare D1 logical binding `DB` from `.openai/hosting.json`.

## Railway

This repository can be started as one fullstack Vinext service. If the project is split later, keep the API/backend service in this same root until a dedicated backend package exists.

Create:

```text
Railway -> New Project -> Deploy from GitHub
```

Service:

```text
Root Directory: repository root
Build Command: npm run build
Start Command: npm run start
Healthcheck Path: /health
```

The same values are committed in `railway.json`, so a Railway deploy from GitHub can read them automatically. Do not set Output Directory on Railway. Let Nixpacks run dependency installation; do not prepend `npm ci` to the Railway build command.

Railway variables:

| Name | Required? | Secret? | Purpose |
| --- | --- | --- | --- |
| `AI_PROVIDER` | No | No | Set to `gigachat` |
| `GIGACHAT_AUTH_KEY` | Yes for AI | Yes | GigaChat OAuth authorization key |
| `GIGACHAT_SCOPE` | No | No | GigaChat scope |
| `GIGACHAT_MODEL` | No | No | GigaChat model |
| `GIGACHAT_BASE_URL` | No | No | GigaChat API base URL |
| `GIGACHAT_AUTH_URL` | No | No | Optional OAuth URL override |
| `GIGACHAT_TIMEOUT_MS` | No | No | Request timeout |
| `MANAGER_WAIT_TIMEOUT_MS` | No | No | Manager wait fallback |
| `ADMIN_EMAIL` | Yes | No | Admin login |
| `ADMIN_NAME` | Yes | No | Admin name |
| `ADMIN_PASSWORD_HASH` | Yes | Yes | Generated by `npm run admin:create` |
| `ADMIN_SESSION_SECRET` | Yes | Yes | Random session secret |
| `PORT` | Railway sets it automatically | No | Runtime port |

Railway database:

The current code uses the D1 binding `DB`. Do not create a PostgreSQL database unless a separate adapter is added. If the project is later migrated to PostgreSQL, add `DATABASE_URL` only with that adapter change.

Important: Railway can run the fullstack app, admin, forms and AI runtime, but it does not provide the Cloudflare D1 `DB` binding. Production persistence for leads/products/support still requires the Cloudflare/Sites environment or a future Railway database adapter.

Railway domain:

The production target is the VPS behind `https://fasadof36.ru`. Railway remains optional staging infrastructure and is not required by the live site.

## Vercel

The current repository is not a standard Next.js or static Vercel project. Its default production build creates a Vinext/Vite `dist/` bundle and expects `npm run start` (`vinext start`) to run the SSR/API server.

Do not set Vercel Output Directory to `dist`, `dist/client`, `.next`, or any guessed path. That deploy can show `404: NOT_FOUND` because the server runtime is not being started.

Use the committed Nitro/Vercel build path:

```text
Build Command: npm run build:vercel
Framework Preset: Other
```

This path is isolated from Railway: `npm run build` still builds the Vinext runtime for Railway, while `npm run build:vercel` sets `NITRO_PRESET=vercel` and builds `.vercel/output` through Nitro.

Do not set a manual Vercel Output Directory. The Nitro Vercel preset emits the Vercel Build Output API folder at `.vercel/output`, and Vercel reads that folder automatically.

Vercel will not provide the current Cloudflare D1 `DB` binding. The public site and server routes can deploy, but D1-backed production persistence still requires Cloudflare/Sites or a separate database adapter.

Vercel variables:

| Name | Required? | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Yes | Canonical production URL |
| `NEXT_PUBLIC_YANDEX_METRIKA_ID` | No | Yandex Metrika |
| `NEXT_PUBLIC_CHAT2DESK_WIDGET_TOKEN` | Yes for chat | Public Chat2Desk widget |
| `NEXT_PUBLIC_CHAT2DESK_URL` | No | Chat2Desk base override |
| `NEXT_PUBLIC_CHAT2DESK_SOCKET_URL` | No | Chat2Desk socket override |
| `NEXT_PUBLIC_CHAT2DESK_STATIC_DOMAIN` | No | Chat2Desk static domain override |

After changing any public env, redeploy the frontend.

## Chat2Desk

Chat2Desk is loaded by `components/Chat2DeskWidget.tsx`, mounted in `app/layout.tsx`.

- Public token variable: `NEXT_PUBLIC_CHAT2DESK_WIDGET_TOKEN`.
- The loader does not run on `/admin`.
- The loader checks script ids to prevent duplicates during navigation.
- Required network allowlist: `https://livechatv2.chat2desk.com`, `https://storage.chat2desk.com`, `wss://livechatv2.chat2desk.com`.

## First Deploy Order

1. Финальный push в GitHub.
2. Проверить D1 production binding `DB` or current production DB target.
3. Deploy backend/fullstack service if Railway is used.
4. Fill backend env.
5. Execute migrations.
6. Check `/health`.
7. Check backend API.
8. Deploy frontend Vercel if the frontend is hosted separately.
9. Fill frontend env.
10. Redeploy frontend after env changes.
11. If frontend/backend split exists, add the Vercel URL to backend allowed origins.
12. Check public website.
13. Check admin.
14. Check Chat2Desk.
15. Connect the final domain only after QA passes.
